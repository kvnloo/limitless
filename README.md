# limitless

The **Limitless Protocol** as a [Hermes Agent](https://github.com/NousResearch/hermes-agent) plugin: a closed loop around one person's peak performance. Sleep, energy and recovery come first, then learning, then flow. The agent observes, suggests one small intervention, and checks what actually happened. It never prescribes.

> [!NOTE]
> This repo is code only. Your data stays on your machines: wearables, phone state and messages are read locally and never committed. Tests use synthetic fixtures, and `tests/test_public_hygiene.py` fails the suite if private paths, tokens or data files are ever committed.

## Principles
- **The pill is a system.** It's a loop, not a score: observe → one low-burden change → lock a prediction → read the outcome → revise only from evidence.
- **Foundation first.** Sleep, energy, nutrition and recovery set the ceiling for everything else.
- **Attention is the scarce resource.** Few notifications, each one useful, the key point first, one tap to act. Decisions are asked for in peak windows, reviews in troughs, and capture can happen anytime.
- **Events, not clock times.** Cues come from waking, the end of a deep-work block or wind-down, never from a fixed schedule.
- **Kind by default.** One habit a week, a start that takes 2 minutes or less, and a skipped day counts as unlogged, not failed.
- **Honest numbers.** Every value says whether it's measured, imported, a proxy or self-reported, and how old it is. Unknown ≠ No.
- **Never:** no drug or supplement advice, no clinical claims, no capability score, no unattended intervention engine.

## What's here (v0, in progress)
- The Hermes plugin: six read-mostly tools and a `pre_llm_call` state card (see [Tools and hook](#tools-and-hook)).
- `limitless/send_gate.py`: the one send policy. 12 h dedupe, a daily cap, a hold while the phone is in Sleep mode, a pending-asks digest folded into the morning brief, and internal ids removed.
- `bin/kevin-push`: the delivery CLI built on the gate (Telegram through a Hermes profile). `KEVIN_PUSH_STRICT=1` exits 3 when the message wasn't delivered.
  - Configure with `KEVIN_PUSH_PROFILE`, `KEVIN_PUSH_TO` (else config `push_profile`, `push_to`; the owner's whole `push via <profile>` reply, applied by the sender ingest job, beats `push_profile`: [docs/push-sender-reply.md](docs/push-sender-reply.md)), `LIMITLESS_STATE` or `LIMITLESS_CONFIG` (`~/.config/limitless/config.json` → `"state"`).
- `limitless/brief_post.py` + `bin/limitless-brief`: finalize and deliver the wake-up brief.
- `limitless/decision_window.py`: decision windows. A job declares `peak`, `trough`, `wind_down` or `anytime`; a provider (`StaticProvider`, `StateFileProvider`) says which window is open from events, never clock times; `decide()` returns deliver, hold or drop with a one-line reason. `send_gate.decide(..., window=...)` takes it as an optional input. Design note: [docs/decision-window.md](docs/decision-window.md).
- `limitless/glide_provider.py` + `limitless/window_chain.py`: `first_known(GlideProvider, EventProvider)` reads the window from [Glide](https://github.com/kvnloo/glide) first (a focus block is `peak` with asks held, the wind-down nudge is `wind_down`; path from `LIMITLESS_GLIDE_ATTENTION` or config `glide_attention`), then from Sleep mode and unlocks. Wind-down comes from an event, never from an evening hour ([docs/glide-wind-down-event.md](docs/glide-wind-down-event.md)). The format is pinned to Glide's own writer by a contract test ([docs/glide-contract.md](docs/glide-contract.md)).
- `limitless/asks.py`: each ask in a host's needs-the-person queue (JSONL at `LIMITLESS_ASKS` or config `asks_path`, read-only) gets a window class from its own fields (decision or deep approval = peak, light approval = anytime, FYI = trough); at most one decision is delivered per peak window, oldest first, the rest hold, FYIs fold into the brief and a focus block holds all but `urgent: true`. `limitless_window` shows `asks` counts with a plain label ([docs/decision-window.md](docs/decision-window.md#asks)).
- `limitless/jobs.py`: event-triggered job specs (wake brief, back from nap, the bedtime question, the habit check-in); `should_fire()` returns deliver, hold, drop or not_triggered with a reason through the decision window and the send gate, and `to_schedule_card()` gives the plain words a Hermes Schedule card could show. Pure functions: nothing sends by itself.
- `limitless/jobs_runner.py` + `bin/limitless-jobs [--send]`: one pass over the jobs, one line per job; dry run unless `--send`, which goes through `kevin-push` (strict) and logs a send only on real Telegram delivery. Poll it with a systemd timer: [docs/limitless-jobs-systemd.md](docs/limitless-jobs-systemd.md).
- Habit check-in gate: the check-in only goes out while a habit week is started (`habit.json` names a habit and its `week_of` is days one to seven); with no started week or after day seven it drops with "no habit week started" or "habit week over" and nothing is sent.
- `limitless/habit_start.py` + `bin/limitless-habit-start "<habit>" [--write]` (or `limitless_habit` with `start` and `confirm: true`, only after the person said yes): start that week, one habit a week; it refuses while a week is running, keeps a finished week as `habit-<week_of>.json`, and is a dry run unless `--write` / `confirm` (exit 3 when refused).
- `limitless/prediction.py` (or `limitless_habit` with `predict` / `receipt` and `confirm: true`, only after the person said yes): locks one prediction per habit week before its check-ins and, after day seven, appends one receipt (supports, contradicts or inconclusive; fewer than three logged days is inconclusive) to `predictions.jsonl` in the state dir, append-only and never rewritten.
- `limitless/wake_proxy.py`: when Sleep mode is not used, a fallback `wake` event from phone screen events (the first unlock or touch after a quiet gap of a few hours; notifications ignored); `jobs.merged_events()` lets a Sleep-mode wake win in the same gap and adds the habit cue one hour after each wake.
- One message per event: `kevin-push --once <job>:<event time>` (or `KEVIN_PUSH_ONCE`) lets only the first delivery per event key through for 12 h, whatever its words; `limitless-jobs --send` passes it on every send, and only a real delivery claims the key.
- Job owners: `limitless-jobs --send` sends the wake brief by running `bin/limitless-brief send` (never a placeholder), and skips any job listed in `external_jobs` / `LIMITLESS_EXTERNAL_JOBS` because its own sender has the real content ([who sends what](docs/limitless-jobs-systemd.md#who-sends-what)).
- One wake-up brief per wake: `bin/limitless-brief send` passes the same key (`jobs_runner.event_key`, the wake event `limitless-jobs` uses), so whichever of the two senders goes first is the only brief; with no wake event it sends with no key.
- Any other sender: `KEVIN_PUSH_ONCE=$(bin/limitless-once-key <job>) kevin-push ...` passes the key `limitless-jobs` uses for that job's event; with no event it prints nothing (exit 3) and the sender sends as before ([docs](docs/limitless-jobs-systemd.md#older-senders)).
- One MIQ prompt per night: the MIQ key is `miq:<night date>` (an event after midnight keeps the previous date until the next wake), and a sender with its own wind-down cue uses `bin/limitless-once-key miq --night`, which prints that key even with no wind-down event yet.
- Short nights: on a day with no quiet gap of 4 h, the first quiet gap of 3 h or more is one wake (`"short": true`, lower confidence, at most one per day), and a wake once seen never moves as later polls add rows; runner verdicts from a screen wake say it is a proxy, not a sleep measure.
- `limitless/aw_reader.py`: the same wake proxy also reads unlocks and app-in-foreground starts from an ActivityWatch-for-Android SQLite copy, opened read-only; set its path with `LIMITLESS_AW_DB` or config key `aw_db` (none by default).
- `limitless/feeds_evidence.py`: a hint for the habit check-in: whether the phone saw one of your feed apps (`LIMITLESS_FEED_APPS`, comma list, or config list `feed_apps`; none by default, so the hint is unknown) opened in the first hour after the wake. The check-in gains one line ("Phone: a feed app was opened in that hour" or "Phone: no feed app seen in that hour", nothing when the phone data does not cover the hour) and `limitless_habit` adds `phone_hint` (seen, not seen or unknown; a proxy); Done, No or Skip stays your tap.
- Passive habit days (config `passive_habit_file`, none by default): an older loop's per-day "first hour feed-free" rows show in `limitless_habit` as `passive` (a proxy, digit-free label such as "habit not started; phone data shows the first hour mostly feed-free"), beside the confirmed week and never as a check-in; the week review keeps its tapped number and adds one phone line ([docs/passive-habit.md](docs/passive-habit.md)).
- Week review (`week_review`): on the first habit cue from day seven of a started week, one message per week (key `week_review:<week_of>`): the habit, "N of M logged days" (skipped and unlogged days stay out of M; none logged says so, never "failed") and a last line "Reply: Keep / Drop"; the first Keep or Drop reply (`habit_replies.decide`, via `bin/limitless-habit-ingest`, dry run unless `--write`) writes `decision` and `decided_at` to `habit.json`, closes the week ("habit week closed") and shows in `limitless_habit`; no reply stays undecided, never a Drop.
- Stop rule and loop row (`limitless/stop_rule.py`): pick a keep-or-drop rule from a short list when the week starts (`--stop-rule` / `stop_rule`: drop it unless most logged days were Done, keep it if any logged day was Done, keep it unless it felt like a chore, no rule). The week review adds one digit-free line before `Reply: Keep / Drop` ("Your rule says: keep it", "drop it" or "your call"; none when unknown). Skipped and unanswered days never count, and unknown is never drop. The person's reply decides, and then one loop row per week (habit, prediction, outcome, rule verdict, decision) is appended to `predictions.jsonl`. `limitless_loop` shows the last few rows in words ([docs/stop-rule.md](docs/stop-rule.md)).
- Habit card (`limitless/habit_card.py`): the habit card as one generic, data-free module a host can reuse for any recurring self-check: a name, an event cue (never a clock time), a start of two minutes or less and the replies Done / No / Skip; `record` (Skip leaves the day with no entry), `week_number` (`{done, logged, unknown}`: unknown is never a No, no rate over seven) and `verdict_inputs` for the stop rule's Keep / Drop; stdlib only, no score. `jobs` and `stop_rule` call it ([docs/habit-card.md](docs/habit-card.md)).
- Experiments (`limitless/prediction.py` + `limitless_experiment`): a prediction locked with `limitless_habit` `predict` (only with confirm) may carry a `falsifier` (the person's words for what result would show it wrong) and `lag_days` (none, one week or two weeks; state metrics only), on the same append-only `predictions.jsonl` row. With a lag the receipt is pending, nothing written, until the lagged span is over, then judged on it; fewer than three days to judge is inconclusive. `limitless_experiment` shows the current experiment and past verdicts in words (running, outcome pending; no experiment locked), prediction and falsifier text only under the raw opt-in, and the week review adds "Experiment: outcome pending (judged later)" while a lag waits; habits only, no score, no streak, read-only ([docs/experiment.md](docs/experiment.md)).
- Evidence ladder (`limitless/strength.py`): how strong a claim is, beside how a value was obtained: measured > derived > association > preregistered > repeated > replicated, read from the locks and receipts already in `predictions.jsonl` (read-only). A contradicted or inconclusive receipt and fewer than three logged days never climb, and replicated needs an outside source, never the person's own data. `limitless_experiment` and `limitless_loop` gain an optional `strength` key in words ("preregistered: one locked week supported it"); the envelope's four fields never change; no score, no number ([docs/evidence-ladder.md](docs/evidence-ladder.md)).
- Habit catalogue (`limitless/habit_catalogue.py`): a fixed, ordered list of at most eight habits, Foundation (sleep, energy, recovery) first and easiest first, the feeds-free first hour on its habit cue at the top; each has an event cue (never a clock time), a two-minute start and one optional environment cue. `limitless_habit_next` offers the next one (untried first; a dropped habit comes back only after every other was tried; kept and running habits never), and after a Drop `bin/limitless-habit-ingest` prints one line, "Next up, if you want it: <name>.", through the tier audit; nothing after Keep. It only suggests: no habit starts without the person's yes ([docs/habit-catalogue.md](docs/habit-catalogue.md)).
- Skill tree (`limitless/skill_tree.py`): the Training Facility's four stacked layers, Foundation, Learning, Flow, Enhancement, with the catalogue's habits and one word per habit (kept, dropped, trying, not tried) from the loop rows already in `predictions.jsonl` and this week's habit; a layer is open when it is Foundation or every earlier layer has a kept habit, else later. `limitless_skill_tree` returns it and `limitless_card_view` kind `skill_tree` shows it as one card. Words only: no score, level, XP or streak; a skipped week is unlogged, never a drop; it never starts a habit ([docs/skill-tree.md](docs/skill-tree.md)).
- Weekly target (`limitless/weekly_target.py`, config `habit_target_days`, default four of seven; wording, not a rule): Done days count toward "most days" of the habit week; No, Skip and unanswered days never reduce it, there is no streak and nothing resets. `limitless_habit` gains `target`, and the check-in, card and week review say "target reached this week" or "on the way" in words only ([docs/weekly-target.md](docs/weekly-target.md)).
- `limitless/habit_replies.py` + `bin/limitless-habit-ingest [--db PATH] [--write]`: closes the habit loop. The first Done, No or Skip the person sends on Telegram after the latest check-in (before it expires) goes into `habit.json` for that day, read from the Hermes session DB opened read-only (`--db`, `LIMITLESS_HERMES_DB` or config key `hermes_db`, none by default); anything else stays unlogged, an existing answer is never overwritten, and it is a dry run unless `--write`.
- `limitless/owner_messages.py`: when the person last wrote to any agent, across every machine's Hermes session DB (`LIMITLESS_OWNER_DBS`, os.pathsep-separated, or config list `owner_dbs`; none by default), read-only and timestamps only; `limitless_state` and the card show it as `messages: wrote recently`, `quiet for a while` or `no data`.
- `limitless/flow_week.py`: the flow criterion, weekly and with no score: deep-work minutes (active time in your `flow_work_apps`, none by default) and feed leak per block-hour (feed apps inside Glide focus blocks) from the ActivityWatch DB, read-only; one line with numbers in the week review and a digit-free label on the card ("flow: deep work up on last week (measured)"); missing days are unknown, not zero ([docs/flow-week.md](docs/flow-week.md)).
- `limitless/body.py` + `limitless_body`: the body fat trend from a body-composition app's per-visit rows (config `body_file`, none by default), the median of the last two weeks against the two before, in words only ("body fat trending down (calibrated estimate)", flat under `body_flat_points`, default half a point; fewer than three visits in either window is "not enough measurements"); raw numbers only under `LIMITLESS_RAW_IN_PROMPT=1`, one digit-free line in the week review, none on the card ([docs/body-trend.md](docs/body-trend.md)).
- `limitless/body_calibration.py`: the scale's body-fat rows fitted to reference scans in the same body file (`method` in config `body_reference_methods`, default dxa), each paired with the nearest scale day within `body_pair_days` (default three; a tie takes the earlier day); two or more pairs fit a constant offset (the median difference), a line only from five pairs and only when it beats the offset leave-one-out; fewer than two is "uncalibrated" in words. The trend then reads the corrected rows ("body fat trending down (calibrated against reference scans)"); config `body_calibration: off` is the old trend exactly; the fit's numbers never leave code ([docs/body-calibration.md](docs/body-calibration.md)).
- `limitless/overnight.py` + `limitless_overnight`: the overnight work queue (config `work_queue_dir`, none by default; `queue/`, `running/`, `done/`, `failed/` with one `<name>.md` each, read by file name and mtime only) as count words: one line in the wind-down (MIQ) message ("Overnight: a few tasks running, one queued") and one in the wake brief ("Overnight: a few done, one failed" since the wind-down event); item names never reach a message ([docs/overnight-digest.md](docs/overnight-digest.md)).
- `limitless/wind_down.py`: one gentle wind-down line inside the MIQ message, never a push of its own ("Screens down and lights low when you're ready."; config `wind_down_line` picks one of a short fixed list, `off` disables it), after the overnight line and before `Reply: Yes / No / Later`, through the tier audit gate; left out when Glide's own wind-down nudge already went out tonight; quiet and Sleep mode hold the whole message as before; no clock time, no advice, no device control ([docs/wind-down.md](docs/wind-down.md)).
- Breathing link (config `wind_down_breathing_link`, off by default) + `limitless_breathing`: a link to the person's own breathing app (a URL or deep link, one token with no space or digit) adds ONE choice to that same wind-down line, "or slow breathing in your app (with live heart data): <link>", "with live heart data" only while the wearable input is fresh by the `limitless_status` rule, else "without heart data"; no new push, no new job, still one line through the tier audit gate; never a breath count, pace or heart number; the tool says link set and heart data in words, the link itself only under the raw opt-in ([docs/breathing-link.md](docs/breathing-link.md)).
- `limitless/rides.py` + `limitless_rides`: bike rides from an exercise-session export (config `rides_file`, none by default; kinds in `ride_kinds`), the last seven days against the seven before, in words only ("rides this week: two, more than last week"; none, one, two or a few; a week with no ride is "none", never "missed"); total minutes only under `LIMITLESS_RAW_IN_PROMPT=1`, heart rate and power never read, one digit-free line in the week review after the body line, none on the card ([docs/rides.md](docs/rides.md)).
- `limitless/anki.py` + `limitless_anki`: this week's Anki reviews, measured from the collection's own review log (`LIMITLESS_ANKI` or config `anki_collection`, none by default; opened read-only, never written), in words only ("no reviews this week", "some reviews this week", "reviewed most days this week"); in a trough window, never a peak, asleep or a focus block, the state card offers "trough: a short Anki review fits now", and the week review gets one words-only Anki line. Unknown is never zero; no streak, no clock time ([docs](docs/anki.md)).
- `limitless/sleep.py` + `limitless_sleep`: sleep over the last seven nights from two sources kept apart, the wearable's nightly summary (config `sleep_file`, none by default) and a phone proxy (the longest screen-off gap starting in the evening half of the day), each with its modality and age, in words only ("sleep: wearable on most nights; phone proxy says longer"); `measured` only when the wearable covers the newest night, a night with neither is unknown, never zero; per-night minutes only under `LIMITLESS_RAW_IN_PROMPT=1`, one digit-free line in the week review after the rides line, none on the card ([docs/sleep.md](docs/sleep.md)).
- `limitless/regularity.py` + `limitless_sleep`'s `regularity` field: how regular sleep times have been over the last fourteen nights, per source and never mixed (the wearable's optional `start`/`end`, else the phone estimate's quiet gap): circular spread of sleep midpoints and wake times plus the drift, in words only ("wearable: sleep times steady", "phone estimate: drifting later", "unknown: too few nights ..." under `regularity_min_nights`, default 4); minutes only under `LIMITLESS_RAW_IN_PROMPT=1`, one digit-free clause on the week review's sleep line, never a clock time or a bedtime ([docs/sleep-regularity.md](docs/sleep-regularity.md)).
- `limitless/sleep_debt.py` + `limitless_sleep_debt`: sleep debt in words, the last three nights against the median of the fourteen before them from the same two sources as `limitless_sleep` (the wearable night first, the phone proxy only for a date it missed), "little sleep debt", "some sleep debt" or "a lot of sleep debt" (shares of the person's own usual night, no norm), "(phone estimate)" when a phone night was used, "unknown: too few nights" otherwise (a missing night is never zero); one line on the state card, none when unknown; minutes only under the raw opt-in; no advice, no score, no clock time ([docs/sleep-debt.md](docs/sleep-debt.md)).
- `limitless/naps.py` + `limitless_naps`: yesterday's naps from phone Sleep mode (an on/off period shorter than `nap_max_h`, default two hours, that is not the longest sleep of its day; an open on is not a nap), in words only ("naps yesterday: one short nap, close to the night" when one ended within `nap_near_night_h`, default four hours, of the night's start); a proxy, unknown when Sleep mode did not change, never none; one line in the wake brief and one in the week review, both through the tier audit gate; start and end times only under `LIMITLESS_RAW_IN_PROMPT=1`; no target, no streak, no nap advice ([docs/naps.md](docs/naps.md)).
- `limitless/presleep_hr.py` + `limitless_presleep_hr`: the wearable's pre-sleep heart rate (config `presleep_hr_file`, one `{night, bpm, modality}` row per night, none by default), the newest wearable night against the median of the fourteen before it, in words only ("pre-sleep heart rate about usual (wearable)", lower or higher than usual); phone rows are never used and a missing night is never zero; unknown with a plain reason under five earlier wearable nights or past a day and a half; beats per minute only under `LIMITLESS_RAW_IN_PROMPT=1`; one digit-free line in the week review through the tier audit gate; no advice, no target, no score ([docs/presleep-hr.md](docs/presleep-hr.md)).
- `limitless/noop_export.py` + `bin/limitless-noop-export [--write]`: fills `sleep_file` and `presleep_hr_file` from a copy of the [NOOP](https://github.com/ryanbr/noop) app's database (config `noop_db`, none by default; opened `mode=ro&immutable=1`, never written): one sleep row per night from wearable sessions only (a phone or import source is skipped; asleep time from the stages, else the efficiency, else no row) and one pre-sleep heart-rate row per night, the mean of the half hour before that night's onset event (under ten samples: no row, never a guess); a dry run with counts in words unless `--write`, which merges by night atomically (0600) so a rerun is `unchanged`; an unknown schema is one plain line and nothing written; no device name, serial or id leaves the database ([docs/noop-export.md](docs/noop-export.md)).
- The NOOP export as an event job (config `"noop_export"`: `off` by default, `dry_run` or `write`): `limitless-jobs --send` runs `noop_export.main` in-process once after a sync that copied the NOOP database (the newest `runs.jsonl` row says so in its `noop` field) and records it in `noop-export.json` (atomic, 0600: the row's epoch seconds, the mode and what it found in words; no path, reading or device id); `dry_run` counts only, `write` merges both files so a rerun is byte-identical; a missing `noop_db` or output file is one plain reason, recorded once, never an error loop; it never sends, pushes or starts a process, shows up as one schedule card on that event (no clock time) and as one `job NOOP export` row in the doctor ([docs/noop-export.md](docs/noop-export.md#as-an-event-job)).
- The NOOP agent MCP server, by hand (config `noop_mcp`: `{"command": [...], "env": {...}}`, off by default): Hermes has no plugin API to register an MCP server, so the plugin registers nothing and never starts it; you add it to the host's `mcp_servers` yourself, only after config `t0_tools` covers `mcp__noop__*` so every number in its results becomes words before it reaches context; one `NOOP MCP` row in the doctor says off, refused or add it by hand ([docs/noop-mcp.md](docs/noop-mcp.md)).
- `limitless/open_wearables.py` + `bin/limitless-ow-export [--write]`: a second, equal source for `sleep_file`: wearable sleep from a self-hosted [Open Wearables](https://github.com/the-momentum/open-wearables) server over its documented sleep-sessions API (config `open_wearables_export`: `off` by default, `dry_run` or `write`; `open_wearables_url`, `open_wearables_user`; the API key only from the environment variable `LIMITLESS_OW_KEY`, never from config.json and never printed), one noop_export-shaped row per night with source `open_wearables` (naps, phone sessions and sessions with no asleep time skipped); a dry run with counts in words unless `--write`, which reuses the NOOP export's atomic merge (0600, a rerun is `unchanged`) and keeps the NOOP row when both sources have a night; every failure is one plain reason, exit 1, nothing written; one `export Open Wearables` row in the doctor ([docs/open-wearables.md](docs/open-wearables.md)).
- `limitless/mock_guard.py`: demo, mock and sample wearable rows are never live. The NOOP and Open Wearables exports drop sessions from a demo device (the demo-seeder id and device-name marks NOOP writes, an Open Wearables seed user, or config `mock_device_patterns`, empty by default) before anything is counted or written, and say in words that some demo rows were left out. Only demo rows is "no wearable data", never a live doctor row. An inputs.json input named for a demo device is state `demo` in `limitless_status`, never recording ([docs/mock-guard.md](docs/mock-guard.md)).
- `limitless/phase.py` + `limitless_phase`: the circadian phase in words, anchored on the wake event (the same one the wake brief and the post-wake peak use), never a clock time: `just_woke` for `phase_light_h` hours after it (default one), then `day`, `evening` once a wind-down event happened, `asleep` while Sleep mode is on, else `unknown` ("no wake event yet"). A circadian daemon's posture file (`LIMITLESS_POSTURE` or config `posture_file`, optional, schema unknown) overrides only when it is fresher than the wake and names a known phase; otherwise `posture_ignored` says why. While `just_woke` the state card adds one line, "Light: outdoor light now helps set the day."; nothing in other phases, no push, no job, no light dose or supplement advice ([docs/phase.md](docs/phase.md)).
- `bin/limitless-owner-beacon write --out PATH`: on a machine whose session DB the plugin host cannot open, writes only the newest user-message time (`{"at", "v": 1}`, mode 0600); copy it over and list it in `LIMITLESS_OWNER_BEACONS` or config `owner_beacons` so the card and catch-up count it ([docs/owner-beacon.md](docs/owner-beacon.md)).
- `bin/limitless-call-brief write [--out PATH]`: today's card as a voice-call brief file (TLDR, then at most 3 digit-free lines; `generated` stamp in a header comment), through the tier gate, written atomically 0600 and only when it changed; `--out` defaults to config `call_brief_file` (relative = state dir); never sends ([docs/call-brief.md](docs/call-brief.md)).

- `scripts/replay_log.py`: replay a delivery log through the gate, read-only, counts only.

## Tools and hook
The repo root is a Hermes directory plugin (`plugin.yaml` + `__init__.py` with `register(ctx)`); all logic is in `limitless/`, which imports and tests without Hermes. Install by placing the repo at `~/.hermes/plugins/limitless/` and adding `limitless` to `plugins.enabled`.

Every tool returns an evidence envelope: `{value, modality, age_h, evidence_tier}`, where modality is `measured`, `imported`, `proxy`, `self_report` or `messages` (message timestamps). Missing data is `value: null` with a `reason`, never a guess.

The `pre_llm_call` hook adds a state card of at most 6 lines to each turn, plus one attention-mode line when a mode is set. It is cached until the window class or a state file changes. Privacy tier T2 is the default: coarse labels only ("sleep short (proxy)", "readiness low (imported)") and every digit masked. Set `LIMITLESS_RAW_IN_PROMPT=1` to opt in to raw numbers. The state dir is `LIMITLESS_STATE`, else `"state"` in `LIMITLESS_CONFIG` (`~/.config/limitless/config.json`); it is read-only except for captures, `quiet.json` (written only by `bin/limitless-quiet-ingest --write`), `apps.json` (written only by `bin/limitless-apps-ingest --write` or the apps ingest job in write mode, with its mark `apps-ingest.json`; `apps-set.json` written only by `bin/limitless-brief send` after a delivered brief told the write), `ranked-drops.json` (written only by `bin/limitless-ranked ingest --write`) and `mode.json` (written only by `/limitless mode`) (the tier audit log is separate, see [docs/privacy-tiers.md](docs/privacy-tiers.md)). Its file shapes are in `limitless/state_reader.py`, with synthetic examples in `tests/fixtures/state/`.

Privacy tiers: T0 = raw values never enter a prompt; T1 = coarse labels made at the source by code (`limitless/labeler.py`) or, optionally, a small local CPU-only model (`LIMITLESS_T1_CMD` or config `t1_model_cmd`, none by default; any error or out-of-set answer falls back to the rule label; `bin/limitless-t1-local` runs a llama.cpp-style CLI on the CPU for it, see [docs/privacy-tiers.md](docs/privacy-tiers.md#local-model-labeler); `bin/limitless-t1-check` runs it once on each of a fixed set of synthetic prompts and says in words whether it agrees with the rule labels, and with config `t1_check_file` set the labeler uses the model only while that saved check meets `t1_min_agreement`, see [docs/privacy-tiers.md](docs/privacy-tiers.md#local-model-check)); T2 = a cloud model sees T1 labels only.

Roadmap: event-triggered jobs for the wake brief, the post-nap message and the bedtime question, offered as Hermes [Schedule cards](https://github.com/NousResearch/hermes-agent/pull/158289) and gated by decision windows. Then a weekly review and N-of-1 experiments. Data comes from adapters for [NOOP](https://github.com/kvnloo/noop) (WHOOP/Oura), Health Connect, smart-scale fusion, a REHIT bike app, ActivityWatch and Anki.
